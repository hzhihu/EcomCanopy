## 主提示词（整段复制）

为一家「一人技术工作室」设计一个单页网站。把它当作专业、有编辑排版感、以工程为主的品牌站来处理，而不是一个普通的 AI SaaS 落地页。

**业务是什么**
品牌名：EcomCanopy（中文副名：易贸森）。署名：hzhihu。
定位：跨境电商 × AI。一名懂跨境业务（订单、库存、海外仓、物流、Listing）的开发者，能以「前线交付工程师」（Forward Deployed Engineer，下称 FDE）的方式，端到端交付 AI Agent 与业务系统。
受众：跨境电商卖家、运营团队、海外仓公司、电商软件服务商、技术负责人、早期创业团队。

**美术方向**
- 只用浅色主题。基础背景 #FCFBF8（暖调米白纸色）。主文字色 #0F1F1A（深森林绿黑）。强调色 #17866A（青绿）。次级文字 #5A6B63。细分隔线 #DEDCD3。
- 全页只允许出现一个深色区块（FDE 区块）：背景 #0F1F1A，文字用米白色。其余部分全部浅色。
- 字体：中文用系统字体栈（PingFang SC / 思源黑体 / Microsoft YaHei），西文与数字用 Inter。标题紧凑、有把握感：桌面端主标题约 56–64px；标题行高 1.15，正文行高 1.75。每个区块上方可放一行小字号、加字距的西文眉标，但要克制，最多每隔一个区块用一次。
- 布局：12 栏栅格，内容最大宽度 1200px，纵向留白充足（区块间距 96–140px）。文字左对齐。允许不对称，避免把所有内容都居中。
- 视觉语言：细线、细的几何线描、小号编号标签、近似等宽的元信息小标签。可以用「树冠分层」作为母题，表现为抽象层叠平面或分层轮廓——只用描边，不要做成有光泽的实心形状。
- 严格避免：渐变、发光、毛玻璃、紫／紫罗兰／蓝色霓虹、模糊光斑、3D 渲染、人物图库照片、用 emoji 当图标、装饰性插画、深色模式切换、把所有元素都做成圆角胶囊。
- 不要在每一节都重复同一种三栏卡片网格。区块结构要有变化：通栏行、错位双栏、横向步骤链、带分隔线的朴素列表、一个有边框的类表格区块。

**页面结构（自上而下），以及需要展示的精确中文文案**

1. 页头（固定在顶部，底部一条细边框，无阴影）：左侧文字标志「EcomCanopy」，下方一行小字「易贸森 · 跨境 AI」；右侧扁平导航，共 8 项，无下拉菜单：首页 · 跨境 AI · AI Agent · 技术服务 · 项目 · 文章 · 关于 · 联系。当前项只用 2px 下划线标记。

2. 首屏：左侧文字，右侧树冠分层图形。上方一行西文眉标「CROSS-BORDER COMMERCE × AI」。主标题：「让 AI 真正融入跨境电商业务。」副段落：「专注跨境电商与 AI 技术融合，围绕真实业务场景构建 AI 应用、Agent 自动化与业务系统解决方案。」下面一行四个小号元信息标签：跨境电商业务 / AI 工程 / Agent 自动化 / FDE 交付。两个行动按钮：主按钮为深色实心「探索技术服务」，次按钮为带箭头的文字链接「查看项目实践 →」。按钮行下方一行细小的说明文字：「当前：AI Skills Hub 开发中 · 差评洞察与 Listing 体检调研中」。

3. 核心能力：三条横向堆叠的带状区块，每条都是通栏一行，左侧是编号（01/02/03），中间一个小标题，一句中文说明，右侧 3–4 个关键词标签。小标题：跨境电商业务 / AI 工程 / 软件工程。不要用圆角卡片；用细线分隔加大量留白。

4. 跨境电商 AI 应用：标题「把 AI 用在真业务上，而不是只会聊天」。结构：左栏一段简短说明；右栏是一个朴素的两列列表，用细线分隔：AI Listing 分析与优化 / AI 商品差评洞察 / AI 产品改进建议 / AI 竞品分析 / AI 运营数据分析 / AI 广告数据分析 / AI 运营助手。每一项：名称 + 一行简短的灰色说明文字。

5. AI Agent 与自动化：标题「把重复、规则化的任务变成可管理的流程」。视觉：一条横向四步链，用小号编号节点与细线连接——理解任务 → 调用工具 → 串联流程 → 回到业务系统。链条下方一行朴素的关键词标签：Agent · Agent Skills · MCP · LLM · RAG · Workflow · n8n。

6. 跨境软件工程：标题「订单、库存、物流，这些系统我做过」。结构：一个略微缩进的列表，左侧一条细边框；条目包括 多平台 OMS / 多仓库 WMS / 库存与订单管理 / 物流渠道 API 集成 / 海外仓履约 / 系统性能优化。右侧不要放「看起来像真的」的数据指标行，改为一行简短说明：「以上为工程实践，不含客户名称与可定位数据。」

7. 唯一的深色区块——跨境 FDE：通栏的 #0F1F1A 区块，米白色文字，内边距充足。标题「深入业务现场，把方案做成能跑的系统」。下面是一条六步的时间线（纵向或横向均可）：业务理解 / 方案设计 / PoC / 工程开发 / 系统集成 / 部署交付。连接线用细的强调绿色，不要用实心卡片。

8. 项目与实验：标题「项目都在真实进度上」。布局：先一行大尺寸的主推行（AI Skills Hub，带状态标签「开发中」），再跟三行较小的条目：AI 差评洞察（「调研中」）、AI Listing 体检（「调研中」）、OMS/WMS 工程实践（「工程实践」）。状态标签：描边样式、全小写不需要大写化、字号小、单色，只有「开发中」用强调色。不要编造数据指标、客户标识或客户名称。

9. 洞察：标题「技术文章」。一个朴素的 3–5 行列表：左侧是日期，用小的等宽字体；中间是中文文章标题；右侧是分类标签；行间用细线分隔；悬停时标题出现下划线。分类：AI for E-commerce / Agent Engineering / Skills & MCP / Automation / Cross-border Systems / Architecture。不要缩略图。

10. 关于 + 联系：双栏分割。左栏：一段简短文字，把这个人写成一个「能力故事」（不写简历、不写职位头衔、不出现真实姓名、不出现公司名），并附上署名「hzhihu」。右栏：联系区块——商务合作 business@ecomcanopy.site，技术交流 hzhihu@ecomcanopy.site，GitHub 链接。附一行说明：「具体报价与周期请通过邮箱沟通。」页脚：文字标志、小字号重复导航、版权行，不要社交图标行。

**交互与状态**
悬停：链接出现轻微下划线或颜色变化；可交互的行边框加深 1px。焦点环用强调绿色。区块进入动画不要求。

**要求**
- 移动端响应式：390px 和 1440px 两个宽度都必须看起来是刻意设计过的。移动端首屏把文字堆在图形上方，导航收进一个菜单按钮（不要做超出简单列表之外的抽屉式汉堡菜单设计），步骤链变成带左侧连接线的纵向列表，深色区块保持通栏。
- 所有可见文案必须是简体中文，只有品牌名和短西文标签除外。
- 不要编造数字、客户标识、客户评价、奖项或「他们都在用」之类的行。
- 整体观感：一个严肃工程师的工作笔记被做成网站——安静、有结构、精确。
